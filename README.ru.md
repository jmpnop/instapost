# InstaPost - Автоматизация публикаций в Instagram

<img width="2912" height="1632" alt="InstaPost Screenshot" src="instapost.png" />

Инструмент командной строки для автоматизации планирования и публикации изображений в Instagram с использованием Facebook Graph API и Dropbox.

## Возможности

### Основная автоматизация
- **Автоматическое планирование**: Добавьте изображения, они автоматически запланируются на следующий доступный слот
- **Мониторинг директории**: Отслеживание новых изображений в реальном времени
- **Умная публикация**: Публикация в запланированное время через Facebook Graph API
- **Поддержка подписей**: Добавление подписей через простые `.txt` файлы
- **Автоматическая организация**: Обработанные файлы перемещаются в папки по датам

### Управление очередью и расписанием
- **Просмотр очереди**: Просмотр всех запланированных постов с таймерами обратного отсчета
- **Гибкое перепланирование**: Изменение времени публикации на лету
- **Отмена**: Удаление постов из очереди в любое время
- **Ребалансировка расписания**: Автоматическое заполнение пропусков путем переноса будущих постов на более ранние слоты
- **Валидация расписания**: Предотвращение планирования на прошедшее время и конфликтов
- **Недельное расписание**: Настройка пользовательских времен публикации для каждого дня

### Надежность и обработка ошибок
- **🛡️ Архитектура устойчивых демонов**: Демоны НИКОГДА не завершаются при ошибках - автоматическое восстановление с экспоненциальной задержкой
- **🔄 Авто-перезапуск**: Интеграция с macOS launchd обеспечивает автоматический перезапуск при сбоях
- **❤️ Мониторинг сердцебиения**: Проверки работоспособности в реальном времени обнаруживают зависшие процессы
- **Логика повторных попыток**: Автоматические повторы при сбоях API с экспоненциальной задержкой (5 попыток)
- **Умная валидация изображений**: Проверка соответствия требованиям Instagram (размеры, вес, соотношение сторон)
- **Безопасность процессов**: Защита от запуска нескольких экземпляров предотвращает конфликты
- **Мониторинг здоровья**: Проверки состояния системы (демоны, диск, расписание)
- **Двухуровневая защита**: Восстановление от ошибок на уровне приложения + надзор за процессами на уровне ОС

### Мониторинг и отладка
- **Логи в реальном времени**: Просмотр логов демонов с фильтрацией и режимом отслеживания
- **История постов**: Просмотр прошлых публикаций с URL и метками времени
- **Панель состояния**: Проверка статуса демонов, времени работы и режима
- **Чистые логи**: Анимация ожидания только в терминале (не в лог-файлах)

### Режимы и тестирование
- **Продакшн режим**: Следует недельному расписанию (по умолчанию)
- **Тестовый режим**: Немедленная обработка для тестирования
- **Облачная интеграция**: Dropbox для хостинга изображений

## Основные компоненты

### Архитектура устойчивых демонов

Все демоны наследуются от базового класса `ResilientDaemon` (`instapost/daemon_base.py`):

**Надежность корпоративного уровня:**
- ✅ **Никогда не завершается при ошибках** - перехватывает все исключения и повторяет попытки вечно
- ✅ **Экспоненциальная задержка** - предотвращает зацикливание ошибок (5с → 10с → 20с → ... → 5мин)
- ✅ **Изящное завершение** - реагирует на сигналы SIGTERM/SIGINT
- ✅ **Мониторинг сердцебиения** - записывает файлы `.{daemon}.heartbeat` для проверок здоровья
- ✅ **Полное логирование ошибок** - захватывает трассировки стека для отладки

**Надзор на уровне ОС (macOS):**
- ✅ **Интеграция с launchd** - автоматический мониторинг процессов
- ✅ **Авто-перезапуск при сбоях** - интервал throttle 10 секунд
- ✅ **Запуск при загрузке/входе** - демоны всегда работают
- ✅ **Переживает**: сбои сети, ошибки API, проблемы файловой системы, перезагрузки, сбои

### 1. Watcher (`instapost/daemons/watcher.py`)
- Мониторит указанные директории на наличие новых изображений
- Валидирует файлы изображений (только JPG, PNG)
- Поддерживает мастер-расписание в `schedule.json` (все посты, прошлые и будущие)
- Реализует безопасность процессов для предотвращения множественных экземпляров
- Показывает анимацию ожидания при отсутствии изменений
- **Устойчивость**: Восстанавливается от ошибок файловой системы, проблем с правами доступа

### 2. Scheduler (`instapost/daemons/scheduler.py`)
- Обрабатывает запланированные посты согласно `WEEKLY_SCHEDULE`
- **Продакшн режим** (по умолчанию): Следует недельному расписанию
- **Тестовый режим**: Когда установлена переменная окружения `TEST_MODE=true`, обрабатывает все посты немедленно
- Управляет полным рабочим процессом публикации:
  1. Валидирует запланированное время
  2. Обрабатывает изображения через загрузку в Dropbox (через `clients/dropbox.py`)
  3. Публикует в Instagram через Facebook Graph API (через `clients/instagram.py`)
  4. Обновляет `processed.json`
- **Устойчивость**: Восстанавливается от сетевых ошибок, сбоев API, таймаутов

### 3. Mover (`instapost/daemons/mover.py`)
- Мониторит `processed.json` для завершенных постов
- Организует обработанные файлы в директории по датам
- Поддерживает рабочую директорию в чистоте
- **Устойчивость**: Восстанавливается от ошибок файловой системы, состояний переполнения диска

## Установка

### Предварительные требования
- Python 3.13+
- Необходимые пакеты: `psutil`, `Pillow`, `watchdog`, `python-dotenv`, `requests`, `pydantic`, `click`, `python-dateutil`

   ```bash
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```
2. **Установите Python и UV**:
   ```bash
   brew install uv
   uv python install 3.13.2
   ```
3. **Установите Git**:
   ```bash
   brew install git
   ```

1. **Клонируйте репозиторий**:
   ```bash

   cd instapost
   ```

## Конфигурация

### Настройка Dropbox API

1. Перейдите в [Dropbox Developer Console](https://www.dropbox.com/developers/apps)
2. Создайте новое приложение со следующими настройками:
   - API: Dropbox API
   - Тип доступа: Full Dropbox
   - Разрешения: files.content.write, files.content.read, sharing.write
3. Запишите ваши DROPBOX_APP_KEY и App DROPBOX_APP_SECRET
4. Запустите команду настройки для получения DROPBOX_REFRESH_TOKEN:

```bash
python -m instapost.cli setup-dropbox
```

5. Следуйте инструкциям для авторизации приложения и получения токена обновления
6. Добавьте токен обновления в ваш файл `.env`
7. Перейдите в папку в Dropbox, которая будет хранить ваши изображения. Скопируйте полный путь точно так, как показано в Dropbox (например, /InstagramPosts или /Apps/InstaPost/images).
8. Добавьте DROPBOX_FOLDER_PATH в ваш файл `.env`

### Настройка Facebook Graph API

Это руководство показывает, как получить **Page Access Token**, который **никогда не истекает** - лучший вариант для автоматизированной публикации в Instagram.

**Преимущества:**
- ✅ **Никогда не истекает** (не требует обслуживания)
- ✅ **Не требуются скрипты обновления**
- ✅ **Настройте один раз, забудьте навсегда**

#### Предварительные требования

Перед началом убедитесь, что у вас есть:
- ✅ Аккаунт Facebook Developer → https://developers.facebook.com/
- ✅ Facebook Page (вы должны быть администратором/владельцем)
- ✅ Instagram Business Account, связанный с вашей Facebook Page
- ✅ Facebook приложение с разрешениями Instagram

#### Шаг 1: Получите краткосрочный User Access Token

**URL:** https://developers.facebook.com/tools/explorer/

1. Выберите ваше **приложение** из выпадающего списка "Meta App" на правой панели
2. В выпадающем списке "User or Page" выберите **"User Token"**
3. В разделе **Permissions** справа отметьте следующие разрешения:
   - ✅ `instagram_basic`
   - ✅ `instagram_content_publish`
   - ✅ `pages_read_engagement`
   - ✅ `pages_manage_metadata` (или `pages_show_list`)
4. Нажмите синюю кнопку **"Generate Access Token"**
5. Следуйте подсказкам для авторизации вашего приложения (Facebook попросит подключить вашу страницу)
6. **Скопируйте токен** из поля "Access Token" - он будет выглядеть так: `EAFWhIOznvsEBO...`

**Примечание:** Этот токен истекает через 1 час, но мы обменяем его сразу в Шаге 2.

#### Шаг 2: Обменяйте на долгосрочный User Token

**Откройте терминал и выполните:**

```bash
curl -X POST "https://graph.facebook.com/v18.0/oauth/access_token" \
  -d "grant_type=fb_exchange_token" \
  -d "client_id=YOUR_APP_ID" \
  -d "client_secret=YOUR_APP_SECRET" \
  -d "fb_exchange_token=PASTE_TOKEN_FROM_STEP_1"
```

**Замените:**
- `YOUR_APP_ID` - Ваш Facebook App ID
- `YOUR_APP_SECRET` - Ваш Facebook App Secret
- `PASTE_TOKEN_FROM_STEP_1` - Токен из Шага 1

**Ответ:**
```json
{
  "access_token": "EAABsbCS1iHgBO...",
  "token_type": "bearer",
  "expires_in": 5183944
}
```

**Скопируйте `access_token`** - вы используете его в Шаге 3.

#### Шаг 3: Получите Page Access Token (Никогда не истекает!)

**Выполните эту команду:**

```bash
curl "https://graph.facebook.com/v18.0/me/accounts?access_token=PASTE_LONG_LIVED_TOKEN_FROM_STEP_2"
```

**Замените:**
- `PASTE_LONG_LIVED_TOKEN_FROM_STEP_2` - Токен из Шага 2

**Ответ:**
```json
{
  "data": [
    {
      "access_token": "EAABsbCS1iHgBO...NEVER_EXPIRES",
      "category": "Brand",
      "name": "Your Page Name",
      "id": "123456789"
    }
  ]
}
```

**🎉 `access_token` в этом ответе - это ваш Page Access Token - он НИКОГДА НЕ ИСТЕКАЕТ!**

#### Шаг 4: Получите Instagram Business Account ID

**Выполните эту команду:**

```bash
curl "https://graph.facebook.com/v18.0/me?fields=instagram_business_account&access_token=YOUR_PAGE_TOKEN"
```

**Замените:**
- `YOUR_PAGE_TOKEN` - Page Access Token из Шага 3

**Ответ:**
```json
{
  "instagram_business_account": {
    "id": "1234567890123456"
  }
}
```

Используйте `instagram_business_account.id` как ваш `INSTAGRAM_BUSINESS_ACCOUNT_ID`.

#### Шаг 5: Обновите ваш файл .env

Добавьте эти учетные данные в ваш файл `.env`:

```bash
# Конфигурация Facebook/Instagram
FACEBOOK_APP_ID=your_app_id_here
FACEBOOK_APP_SECRET=your_app_secret_here
FACEBOOK_ACCESS_TOKEN=your_page_access_token_from_step_3
INSTAGRAM_BUSINESS_ACCOUNT_ID=your_instagram_business_account_id_from_step_4
```

**✅ Готово! Этот токен будет работать вечно (пока ваше приложение и страница остаются активными).**

## 📅 Формат недельного расписания

Формат: `WEEKLY_SCHEDULE="0:07:00,2:11:00,4:17:00,5:09:00,6:18:00"`

- Дни: 0=Понедельник, 1=Вторник, ..., 6=Воскресенье
- Время в 24-часовом формате (ЧЧ:ММ:СС)
- Пример расписания:
  - Понедельник (0): 07:00
  - Среда (2): 11:00
  - Пятница (4): 17:00
  - Суббота (5): 09:00
  - Воскресенье (6): 18:00

## 🛠️ Использование

**CLI `instapost` - универсальный командный центр для всех операций.**

### Быстрый старт (macOS - Рекомендуется)
```bash
# 1. Установите launchd для авто-перезапуска (ОДНОРАЗОВАЯ НАСТРОЙКА)
uv run instapost install-launchd

# 2. Запустите все демоны (watcher, scheduler, mover)
uv run instapost start

# 3. Проверьте статус (показывает здоровье сердцебиения)
uv run instapost status

# Демоны теперь работают вечно:
#  ✅ Авто-перезапуск при сбоях
#  ✅ Запуск при загрузке/входе
#  ✅ Никогда не останавливаются
```

### Быстрый старт (Ручной режим)
```bash
# Запустите все демоны (без авто-перезапуска)
uv run instapost start

# Проверьте статус
uv run instapost status

# Остановите все демоны
uv run instapost stop

# Примечание: Установите launchd для защиты авто-перезапуска
```

### Управление демонами
```bash
# Настройка launchd (macOS - Рекомендуется)
uv run instapost install-launchd    # Включить авто-перезапуск при сбоях
uv run instapost uninstall-launchd  # Отключить авто-перезапуск

# Запуск/Остановка демонов
uv run instapost start          # Запустить все демоны
uv run instapost stop           # Остановить все демоны (временно)
uv run instapost restart        # Перезапустить все демоны
uv run instapost status         # Проверить статус демонов + здоровье сердцебиения
uv run instapost health         # Проверка здоровья системы

# Статус показывает:
#  - PID демонов и время работы
#  - Возраст сердцебиения (обнаруживает зависшие процессы)
#  - Режим управления (launchd vs ручной)
```

### Управление очередью
```bash
instapost queue                              # Просмотр запланированных постов
instapost cancel <filename>                  # Удалить из расписания
instapost reschedule <filename> <new-time>   # Изменить время публикации
instapost rebalance                          # Предпросмотр оптимизации расписания
instapost rebalance --apply                  # Оптимизировать расписание (заполнить пропуски)
```

### Ребалансировка расписания

**Автоматическая оптимизация расписания публикаций путем заполнения пропусков:**

Команда rebalance находит пустые временные слоты в вашем недельном расписании и заполняет их, перемещая посты из более позднего времени на более ранние доступные слоты.

**Когда использовать:**
- После отмены или удаления постов (создает пропуски в расписании)
- Когда система была выключена и пропустила время публикации
- Для уплотнения расписания и более ранней публикации изображений

**Как это работает:**
```bash
# Предпросмотр изменений (dry-run)
uv run instapost rebalance

# Вывод:
# Gaps found: 260
# Posts to move: 76
# Would move 76 posts to fill 260 gaps
#
# Changes (first 10):
# 0d6242d9-59e9-48d3-aa88-9dfe003415c3.jpg
#   2026-01-28 11:00 → 2026-01-23 17:00

# Применить ребалансировку
uv run instapost rebalance --apply
```

**Функции безопасности:**
- Всегда запускается в режиме dry-run по умолчанию (сначала предпросмотр изменений)
- Перемещает только необработанные посты (уже опубликованные изображения остаются в истории)
- Сохраняет хронологический порядок (посты сохраняют относительный порядок)
- Заполняет сначала самые ранние пропуски (перемещает посты на ближайшие доступные слоты)

### Добавление подписей к постам

**InstaPost поддерживает автоматическое определение подписей через `.txt` файлы:**

```bash

```

**Формат подписи:**
- Простые текстовые файлы (расширение `.txt`)
- Должно совпадать с именем файла изображения: `image.jpg` → `image.txt`
- Поддерживается однострочный или многострочный формат
- Поддерживает эмодзи и хештеги
- **Опционально** - если нет `.txt` файла, пост публикуется без подписи

**Пример с многострочной подписью:**
```bash
cat > images/vacation.txt << 'EOF'
Потрясающий отпуск на Гавайях! 🏝️

#Путешествия #Гавайи #Рай #Отпуск
#ПляжнаяЖизнь #Лето2025

# Будет запланировано с полной многострочной подписью
```

**Как это работает:**
1. Watcher обнаруживает оба `image.jpg` и `image.txt`
2. Подпись читается из `.txt` файла
3. Подпись сохраняется в `schedule.json`
4. Scheduler передает подпись в Instagram при публикации

## 📂 Структура файлов

### Основные директории
- `images/`: Директория для изображений к публикации
  - Файлы обрабатываются в алфавитном порядке
  - Обрабатываются только JPG/PNG файлы
  - Рекомендуемый максимальный размер: 8MB на файл

- `processed/`: Успешно опубликованные изображения перемещаются сюда
  - Организованы по дате (YYYY-MM-DD)
  - Исходные имена файлов сохраняются
  - Содержит метаданные JSON для каждого изображения

- `logs/`: Лог файлы
  - `instapost.log`: Основной лог приложения
  - `instapost.error.log`: Лог только ошибок
  - Ротация ежедневно, хранение логов 7 дней
  - Максимальный размер: 10MB на лог файл

### Конфигурационные файлы
- `.env`: Переменные окружения (никогда не коммитьте!)
  - Содержит чувствительные учетные данные
  - Требуется для запуска приложения
  - Используйте `chmod 600 .env` для защиты

### Файлы данных (управляются автоматически)
- `schedule.json`: Мастер-расписание всех постов (обработанные + ожидающие)
  - Содержит полную запись всех запланированных постов, как прошлых, так и будущих
  - Формат: Массив `{"filename": "...", "time": "2023-01-01T12:00:00", ...}`
  - Автоматически обновляется наблюдателем при добавлении новых изображений
  - Может редактироваться вручную при остановленных сервисах

- `processed.json`: Журнал успешно опубликованных постов
  - Отслеживает какие посты из schedule.json были опубликованы
  - Используется для определения того, что выполнено, а что ожидает
  - Предотвращает дублирование публикаций
  - Формат: Массив `{"filename": "...", "posted_at": "timestamp", "url": "...", ...}`

**Как они работают вместе:**
- `schedule.json` - источник истины для всех запланированных постов
- `processed.json` - записывает какие элементы были успешно опубликованы
- Пост ожидает публикации, если он есть в `schedule.json`, но отсутствует в `processed.json`
- Пост завершен, если он присутствует в обоих файлах

- `db_token.json`: API токены (управляются автоматически)
  - Хранит OAuth токены
  - Автоматически обновляется по необходимости
  - Должен быть включен в `.gitignore`

## 🛡️ Архитектура устойчивых демонов

Демоны InstaPost разработаны так, чтобы **НИКОГДА не останавливаться**, даже при возникновении ошибок.

### Двухуровневая защита

**1. Уровень приложения** (базовый класс `ResilientDaemon`):
- ✅ Перехватывает ВСЕ исключения (сетевые ошибки, сбои API, проблемы файловой системы)
- ✅ Логирует ошибки с полными трассировками стека для отладки
- ✅ Ожидает с экспоненциальной задержкой (5с → 10с → 20с → ... → 5мин)
- ✅ Повторяет попытки вечно до успеха операции
- ✅ Завершается только при явных сигналах остановки (SIGTERM/SIGINT)

**2. Уровень ОС** (macOS launchd):
- ✅ Мониторит здоровье процесса
- ✅ Авто-перезапуск при сбоях (даже если интерпретатор Python аварийно завершился)
- ✅ Интервал throttle 10 секунд предотвращает циклы перезапуска
- ✅ Автоматически запускает демоны при загрузке/входе
- ✅ Переживает перезагрузки системы и выход пользователя

### Что это значит

Ваши демоны **переживут**:
- ❌ Сбои сети (ошибки DNS, таймауты API, обрывы соединения)
- ❌ Ошибки API (временные проблемы Instagram/Facebook/Dropbox)
- ❌ Ошибки файловой системы (диск заполнен, доступ запрещен)
- ❌ Исключения Python (любая неожиданная ошибка в коде)
- ❌ Убийство процессов (кроме явного `instapost stop`)
- ❌ Сбои из-за нехватки памяти
- ❌ Перезагрузки системы
- ❌ Выход/вход пользователя

### Конфигурация launchd

Установка создает plist файлы в `~/Library/LaunchAgents/`:
```xml
<key>KeepAlive</key>
<dict>
    <key>SuccessfulExit</key>
    <false/>        <!-- Перезапуск даже при чистом выходе -->
    <key>Crashed</key>
    <true/>         <!-- Всегда перезапуск при сбоях -->
</dict>
<key>ThrottleInterval</key>
<integer>10</integer>  <!-- Ожидание 10с между перезапусками -->
```

См. `launchd/README.md` для подробной документации launchd.

```bash
# Удалите старые обработанные файлы (старше 30 дней)
find processed/ -type f -mtime +30 -delete

# Очистите лог файлы
find logs/ -type f -name "*.log" -mtime +7 -delete
```

## 🔍 Проверка разрешений приложения

### Разрешения Dropbox
1. **Перейдите в Dropbox App Console**:
   - Посетите: https://www.dropbox.com/developers/apps
   - Выберите ваше приложение из списка

2. **Проверьте настройки OAuth 2**:
   - В разделе "OAuth 2" проверьте, что эти области включены:
     - `files.content.write` (требуется для загрузки файлов)
     - `sharing.write` (требуется для создания общих ссылок)
     - `account_info.read` (требуется для базовой информации об аккаунте)

3. **Проверьте разрешения токена доступа**:
   - Перейдите: https://www.dropbox.com/account/connected_apps
   - Найдите ваше приложение и нажмите "View permissions"
   - Убедитесь, что все необходимые разрешения предоставлены

4. **Перегенерируйте токен при необходимости**:
   - Если разрешения неправильные, вам нужно:
     1. Отозвать токен в настройках аккаунта Dropbox
     2. Удалить локальный файл `db_token.json`
     3. Перезапустить процесс настройки

### Разрешения Facebook Developer Portal
1. **Перейдите в Facebook Developer Portal**:
   - Посетите: https://developers.facebook.com/apps/
   - Выберите ваше приложение

2. **Проверьте статус проверки приложения**:
   - В левой боковой панели нажмите "App Review"
   - Убедитесь, что ваше приложение в режиме "Live" (не Development mode)
   - Проверьте, что все необходимые разрешения одобрены (с зелеными галочками)

3. **Проверьте необходимые разрешения**:
   - Перейдите в "App Settings" > "Advanced"
   - В разделе "App Review for Live Apps" убедитесь, что эти разрешения одобрены:
     - `instagram_basic`
     - `instagram_content_publish`
     - `pages_show_list`
     - `pages_read_engagement`

4. **Проверьте разрешения токена**:
   - Перейдите: https://developers.facebook.com/tools/debug/accesstoken/
   - Вставьте ваш токен доступа и нажмите "Debug"
   - Проверьте, что все необходимые разрешения перечислены в "Permissions"
   - Проверьте дату истечения токена

5. **Проверьте подключение Instagram аккаунта**:
   - Перейдите: https://business.facebook.com/settings/instagram-api
   - Убедитесь, что ваш Instagram Business Account подключен
   - Проверьте, что правильная Facebook Page связана

## 🔒 Лучшие практики безопасности

### Запуск не от root
Никогда не запускайте приложение от root. Вместо этого:
```bash
# Создайте выделенного пользователя
sudo useradd -r -s /sbin/nologin instapost

# Установите владельца файлов приложения
sudo chown -R instapost:instapost /path/to/instapost

# Запустите от выделенного пользователя
sudo -u instapost python -m instapost.daemons.watcher
```

### Защита чувствительных файлов
```bash
# Установите ограничительные разрешения на чувствительные файлы
chmod 600 .env db_token.json
chmod 700 logs

# Проверьте разрешения
ls -la .env db_token.json
```

### Безопасность API
- Ротируйте API токены каждые 90 дней
- Используйте принцип минимальных привилегий для разрешений API
- Мониторьте использование API на подозрительную активность

## 🔄 Резервное копирование и восстановление

### Регулярные резервные копии
```bash
# Создайте резервную копию критических файлов
BACKUP_DIR=~/instapost_backup_$(date +%Y%m%d)
mkdir -p $BACKUP_DIR
```

1. **Восстановление из резервной копии**:
   ```bash

   cp -i instapost_backup_YYYYMMDD/* ./
   ```

2. **Восстановление после сбоя**:
   - Проверьте логи: `tail -n 100 logs/instapost.log`
   - Проверьте, что API токены все еще действительны
   - Проверьте место на диске и разрешения

## 📈 Соображения производительности

### Обработка больших объемов
- Обработка до 1,000 изображений в день в пределах лимитов API
- Каждое изображение занимает приблизительно 10-30 секунд для обработки
- Мониторьте лимиты API в Facebook Developer Portal

### Требования к ресурсам
- **CPU**: Минимальные (достаточно одного ядра)
- **Память**: ~100MB базовые + ~50MB на одновременную загрузку
- **Диск**: Рекомендуется 1GB свободного места для логов и временных файлов

### Советы по масштабированию
1. Для большого объема (>100 изображений/день):
   - Реализуйте систему очередей
   - Рассмотрите ограничение скорости
   - Мониторьте квоты API

2. Для больших файлов:
   - Предварительно оптимизируйте изображения перед добавлением в `images/`
   - Используйте подходящие размеры изображений (рекомендуется 1080x1080px)
